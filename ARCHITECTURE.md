# MTG Artist Gallery — Architecture

## Technology

The application is intentionally simple.

- HTML
- CSS
- Vanilla JavaScript
- JSON
- Python for data generation
- Scryfall bulk data
- MAMP for local development
- Static hosting compatible

No JavaScript framework is currently used.

## Home view

The parameter-free route shows the home view; artist, set and About views use query parameters and browser history. The home collage randomly selects eight distinct artworks from the 30 entries in `data/home-artworks.json`. Each entry contains an `illustration_id` and the corresponding `artistSlug`, which is used to fetch the existing artist shard for its image and attribution. This hand-maintained file is not generated by `tools/update_data.py`; see `tools/README.md` for maintenance and validation.

## Artist links

`data/artist-links.json` is hand-maintained and keyed by artist slug. It is not generated or overwritten by `tools/update_data.py`. At startup `loadData()` fetches it and `mergeArtistLinks()` attaches a filtered `links` object (allowed keys, `https://` only) to each matching artist. A missing or invalid file is ignored. Validate with `python3 tools/validate_links.py`.
